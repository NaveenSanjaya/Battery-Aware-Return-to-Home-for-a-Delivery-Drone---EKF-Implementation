\section{Tools and code structure}\label{sec:i_structure}\label{sec:i_run_flight}\label{sec:i_loop}\label{sec:i_day4}
%--------------------------------------------------------------------------------------------------

The project uses base MATLAB only, with a time step of 1\,s. Every run fixes the random seed, so it can be repeated exactly, and runs that are compared share the same sensor noise. The code in \texttt{drone\_battery\_ekf/} is split into short files that each do one job: \texttt{config/} holds the battery and sensor parameters and the OCV curve; \texttt{sim/} the true 2-RC battery, the sensors, the drone's flight phases, the routes and the performance measures; \texttt{estimators/} the EKF (stages A--C) and charge counting; and \texttt{decision/} the trip cost, the probability of a safe return and the four policies.

Every second, a flight runs the same loop: the drone model gives the current demand, the true battery responds, the sensors add bias and noise, the EKF and charge counting update, and, in return-to-home missions, the policy decides whether to turn back. \texttt{run\_flight.m} flies experiments E1--E8 and \texttt{run\_mission\_rth.m} the return-to-home missions. Four main scripts reproduce every result: \texttt{main\_day2\_simulator.m} (simulator check), \texttt{main\_day3\_ekf.m} (E1--E2), \texttt{main\_day4\_experiments.m} (E3--E8, about 20\,s for the 300 flights of E8) and \texttt{main\_day5\_rth.m} (demonstration, 500-mission Monte Carlo in about 95\,s, and threshold sweep).
