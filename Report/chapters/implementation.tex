\section{Code structure and one simulated flight}\label{sec:i_structure}\label{sec:i_run_flight}\label{sec:i_loop}\label{sec:i_day4}
%--------------------------------------------------------------------------------------------------

All runs use fixed random seeds, so the results are reproducible and runs that are compared share the same sensor noise. The code in \texttt{drone\_battery\_ekf/} is split into short files in four folders: \texttt{config/} (battery and sensor values, OCV curve), \texttt{sim/} (the ``real'' battery, sensors, flight phases, routes and scoring), \texttt{estimators/} (the EKF and charge counting) and \texttt{decision/} (trip cost, $P_{\text{safe}}$ and the four policies).

Every flight runs the same loop once per second: the drone model gives the current for the flight phase, the simulated battery responds, the sensors add bias and noise, the EKF and charge counting update, and, in return-home missions, the policy decides whether to turn back. The loop stops when the drone lands or the battery dies. Four main scripts reproduce every result: \texttt{run1\_simulator\_check.m}, \texttt{run2\_filter\_E1\_E2.m}, \texttt{run3\_stress\_tests\_E3\_E8.m} (about 20\,s) and \texttt{run4\_return\_home.m} (demonstration, Monte Carlo study in about 95\,s, and threshold sweep).

\section{The EKF in code}\label{sec:i_ekf}
%--------------------------------------------------------------------------------------------------

Listing~\ref{lst:i_ekf_core} shows one EKF step from \texttt{ekf\_step.m}. It follows the three steps of Section~\ref{sec:bg_kf}:
\begin{itemize}
  \item \textbf{Predict} (lines 16--30): move the state forward~\eqref{eq:m_f_soc}--\eqref{eq:m_f_r0}, build $F$, $G$ and $Q$~\eqref{eq:m_F},~\eqref{eq:m_Q}, and grow the uncertainty;
  \item \textbf{Compare} (lines 33--39): compute the expected voltage~\eqref{eq:m_h}, the innovation, $H$ and $S$;
  \item \textbf{Correct} (lines 42--46): apply the gain and the Joseph-form covariance update~\eqref{eq:m_joseph}.
\end{itemize}
With only one measurement, $S$ is a single number, so the gain needs a division rather than a matrix inverse. The code always carries all five states; a stage that does not estimate a state gives it zero uncertainty and zero process noise, so it never changes.

\section{The return-home rule in code}\label{sec:i_decision}
%--------------------------------------------------------------------------------------------------

\texttt{decision/p\_safe\_return.m} (Listing~\ref{lst:i_psafe} in Appendix~\ref{app:code}) follows the three steps of Section~\ref{sec:m_rth}: it computes the charge needed to get home and the margin, combines the EKF's SoC uncertainty with the trip allowance, and returns $P_{\text{safe}}$. The normal distribution is written as $\Phi(x) = \tfrac{1}{2}\,\mathrm{erfc}(-x/\sqrt{2})$, which is built into base MATLAB, so no toolbox is needed.
